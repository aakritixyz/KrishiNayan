# Equipment & Input Sharing Feature Design

## Overview
This document outlines the design for KrishiNayan's Equipment & Input Sharing feature—a community rental marketplace where farmers can list, search, and rent expensive farming equipment (sprayers, sensors, harvesters) from nearby farmers, with optional surplus input sharing (seeds/fertilizers) and bulk-purchase pooling.

## Design Principles
- **Simplicity**: Minimal steps, visual-first interface for low-tech literacy
- **Trust**: Verified identities, transparent ratings, clear availability
- **Local Focus**: GPS-based search within 10-50km radius
- **Farmer-First**: Voice notes, minimal text, big buttons, regional language support

## Row Level Security Policies
```sql
-- Equipment listings RLS
alter table public.equipment_listings enable row level security;

-- Owners can see and edit their own listings
create policy "owners can view own listings" on public.equipment_listings
  for select using (auth.uid()::integer = owner_id);

create policy "owners can insert own listings" on public.equipment_listings
  for insert with check (auth.uid()::integer = owner_id);

create policy "owners can update own listings" on public.equipment_listings
  for update using (auth.uid()::integer = owner_id);

create policy "owners can delete own listings" on public.equipment_listings
  for delete using (auth.uid()::integer = owner_id);

-- Everyone can view active listings
create policy "everyone can view active listings" on public.equipment_listings
  for select using (status = 'active' and is_available = true);

-- Rental requests RLS
alter table public.equipment_rental_requests enable row level security;

create policy "users can view own requests" on public.equipment_rental_requests
  for select using (auth.uid()::integer = renter_id or auth.uid()::integer = owner_id);

create policy "renters can create requests" on public.equipment_rental_requests
  for insert with check (auth.uid()::integer = renter_id);

create policy "owners can update requests" on public.equipment_rental_requests
  for update using (auth.uid()::integer = owner_id);

create policy "renters can update own requests" on public.equipment_rental_requests
  for update using (auth.uid()::integer = renter_id);

-- Reviews RLS
alter table public.equipment_reviews enable row level security;

create policy "users can view all reviews" on public.equipment_reviews
  for select using (true);

create policy "verified renters can create reviews" on public.equipment_reviews
  for insert with check (
    auth.uid()::integer = reviewer_id and 
    verified_rental = true
  );
```

## Location-Based Search Implementation

### Haversine Formula for Distance Calculation
```python
import math
from typing import List, Tuple

def haversine_distance(lat1: float, lon1: float, lat2: float, lon2: float) -> float:
    """
    Calculate the great circle distance between two points
    on the earth (specified in decimal degrees)
    Returns distance in kilometers
    """
    # Convert decimal degrees to radians
    lat1, lon1, lat2, lon2 = map(math.radians, [lat1, lon1, lat2, lon2])
    
    # Haversine formula
    dlat = lat2 - lat1
    dlon = lon2 - lon1
    a = math.sin(dlat/2)**2 + math.cos(lat1) * math.cos(lat2) * math.sin(dlon/2)**2
    c = 2 * math.asin(math.sqrt(a))
    
    # Radius of earth in kilometers
    r = 6371
    
    return c * r

def find_equipment_within_radius(
    user_lat: float, 
    user_lon: float, 
    radius_km: float,
    equipment_type: str = None,
    available_from: str = None,
    available_until: str = None
) -> List[dict]:
    """
    Find equipment listings within a given radius of user's location
    """
    from sqlalchemy import and_, or_
    from app.models.equipment_listing import EquipmentListing
    
    # Build base query
    query = EquipmentListing.query.filter(
        and_(
            EquipmentListing.status == 'active',
            EquipmentListing.is_available == True
        )
    )
    
    # Add equipment type filter if specified
    if equipment_type:
        query = query.filter(EquipmentListing.equipment_type == equipment_type)
    
    # Add date availability filters
    if available_from:
        query = query.filter(EquipmentListing.available_from <= available_from)
    if available_until:
        query = query.filter(EquipmentListing.available_until >= available_until)
    
    # Get all matching listings
    listings = query.all()
    
    # Filter by distance using Haversine formula
    nearby_listings = []
    for listing in listings:
        distance = haversine_distance(
            user_lat, user_lon, 
            listing.latitude, listing.longitude
        )
        if distance <= radius_km:
            nearby_listings.append({
                'listing': listing,
                'distance_km': round(distance, 1)
            })
    
    # Sort by distance
    nearby_listings.sort(key=lambda x: x['distance_km'])
    
    return nearby_listings
```

```python
def calculate_trust_score(user_id: int) -> dict:
    """
    Calculate comprehensive trust score for a user
    Returns score 0-100 with component breakdown
    """
    from app.models.equipment_review import EquipmentReview
    from app.models.equipment_rental_request import EquipmentRentalRequest
    from app.models.user_equipment_trust import UserEquipmentTrust
    
    # Get user's rental history
    rentals_as_owner = EquipmentRentalRequest.query.filter_by(
        owner_id=user_id, 
        status='completed'
    ).count()
    
    rentals_as_renter = EquipmentRentalRequest.query.filter_by(
        renter_id=user_id, 
        status='completed'
    ).count()
    
    total_completed = rentals_as_owner + rentals_as_renter
    
    # Get ratings received
    reviews_received = EquipmentReview.query.filter_by(
        reviewee_id=user_id
    ).all()
    
    # Calculate component scores
    scores = {
        'completion_rate': 0,
        'rating_score': 0,
        'activity_score': 0,
        'verification_score': 0,
        'response_score': 0,
        'overall': 0
    }
    
    # 1. Completion Rate (30% weight)
    total_requests = EquipmentRentalRequest.query.filter(
        or_(
            EquipmentRentalRequest.owner_id == user_id,
            EquipmentRentalRequest.renter_id == user_id
        )
    ).count()
    
    if total_requests > 0:
        completion_rate = (total_completed / total_requests) * 100
        scores['completion_rate'] = min(completion_rate, 100)
    
    # 2. Rating Score (25% weight)
    if reviews_received:
        avg_rating = sum(r.overall_rating for r in reviews_received) / len(reviews_received)
        scores['rating_score'] = (avg_rating / 5) * 100
    
    # 3. Activity Score (20% weight)
    # More activity = higher trust (up to a point)
    activity_score = min(total_completed * 2, 100)
    scores['activity_score'] = activity_score
    
    # 4. Verification Score (15% weight)
    user = User.query.get(user_id)
    verification_score = 0
    if user.identity_verification_status == 'verified':
        verification_score += 50
    if user.phone:
        verification_score += 30
    if user.profile_completed:
        verification_score += 20
    scores['verification_score'] = verification_score
    
    # 5. Response Score (10% weight)
    # Calculate average response time (faster = higher score)
    # Implementation would track message response times
    scores['response_score'] = 80  # Placeholder
    
    # Calculate weighted overall score
    weights = {
        'completion_rate': 0.30,
        'rating_score': 0.25,
        'activity_score': 0.20,
        'verification_score': 0.15,
        'response_score': 0.10
    }
    
    overall_score = sum(
        scores[key] * weights[key] 
        for key in scores.keys() 
        if key != 'overall'
    )
    
    scores['overall'] = round(overall_score, 1)
    
    return scores
```

```python
    ).first()
    
    if existing_review:

    # Check rating range
    if not (1 <= review_data.get('overall_rating', 0) <= 5):
        return False, "Rating must be between 1 and 5"
    
    # Check for inappropriate content (basic filter)
    prohibited_words = ['scam', 'fraud', 'cheat', 'fake']

    if any(word in comment for word in prohibited_words):
        return False, "Review contains inappropriate language"
    
    return True, "Review validated"
```

## Risk Mitigation

### Trust & Safety Risks
- **Risk**: Equipment damage or theft
- **Mitigation**: Security deposits, verification system, insurance integration
- **Risk**: Fake listings or scams
- **Mitigation**: Phone verification, identity verification, review system
- **Risk**: Payment disputes
- **Mitigation**: Clear terms, escrow system, dispute resolution process

### Technical Risks
- **Risk**: Poor GPS accuracy in rural areas
- **Mitigation**: Manual location selection, landmark-based directions
- **Risk**: Limited internet connectivity
- **Mitigation**: Offline mode, data compression, lite version
- **Risk**: Image upload failures
- **Mitigation**: Retry logic, compression, progress indicators

### Adoption Risks
- **Risk**: Low tech literacy
- **Mitigation**: Visual interface, voice support, hands-on training
- **Risk**: Resistance to sharing equipment
- **Mitigation**: Trust building, success stories, community champions
- **Risk**: Seasonal demand fluctuations
- **Mitigation**: Diversify equipment types, bulk purchase options

## Conclusion

This Equipment & Input Sharing feature design prioritizes simplicity, trust, and local relevance for Indian farmers. The phased rollout allows for learning and iteration, while the comprehensive API and database design provide a solid foundation for scaling. The farmer-friendly UI flows account for low tech literacy through visual-first design, voice support, and regional language capabilities.

The integration with existing KrishiNayan infrastructure (user management, location data, Supabase backend) ensures a seamless addition to the current platform while maintaining consistency with the overall architecture.
